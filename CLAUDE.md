# Vocaboo — session handoff note

Mobile-first PWA for memorizing English vocabulary (字卡 FSRS 排程 / 選擇題 / 拼字 /
練習題本). Built by a teacher ("shuanmaker") for their students, who use it on phones.
Two banks: 學測 Level 1–6 (`data/gsat.json`) and 教材單字 (`data/material.json`).
Read `README.md` for data formats, build scripts, and credits — this file is only the
operational handoff for whoever (human or Claude) picks the project up next.

## Live site
- **Student URL:** https://shuanmaker-web.github.io/vocab-app/
- **Hosting:** GitHub Pages, repo `shuanmaker-web/vocab-app`, source = branch `main`,
  folder `/` (root). Every push to `main` auto-rebuilds Pages (~1 min).
- Vanilla static site — no build step, no framework, no bundler. The files in the repo
  root ARE the site.

## How to make a change (the whole workflow)
1. Edit files in the repo (`index.html`, `style.css`, `app.js`, `data/*.json`, …).
2. **If you changed anything in the service worker's `CORE` list (see `sw.js`) — i.e. any
   file students actually load — BUMP `VERSION` in `sw.js`** (`v80` → `v81` → …). This is
   how returning students get the new version; skip it and they keep seeing the old cached
   app. Doc/tooling-only changes (this file, `tools/`, `README.md`) do NOT need a bump.
3. `git add -A && git commit -m "..." && git push origin main`.
4. Wait ~1 min, then load the URL and hard-refresh (Ctrl/Cmd+Shift+R) to confirm.

## Students are LIVE — verify BEFORE you push ⚠️
Students already use the published site on their phones, and there is **no separate staging
site**: a push to `main` goes live in ~1 min. Treat `main` as production.
- **Verify before pushing, not after.** Before `git push`, run the working copy and actually
  exercise the change, then show the owner evidence (screenshot / test result). Reliable way:
  `python3 -m http.server` in the repo dir + headless Chromium (Playwright is installed) to
  load it and drive the feature; or the built-in browser against a local server. Only push
  once it's confirmed working.
- For risky or owner-flagged changes, get the owner's OK on the verification first, then push.

## Don't break existing students' saved data ⚠️
Each student's progress (FSRS cards, practice results, backups) lives in **their own phone's
IndexedDB** — it is not on any server and cannot be recovered if a change corrupts it.
- Before any change, tell the owner in one line whether it could affect existing features or
  saved progress.
- Anything touching the data shape, storage keys, IndexedDB schema/version, backup format, or
  `sw.js` must stay **backward-compatible** with data already on students' devices. If a
  migration is unavoidable, make it additive and non-destructive, and flag it first.

## For a fresh Claude session
- Attach + clone: `add_repo(owner=shuanmaker-web, repo=vocab-app, access=push)` then the
  clone it instructs. Push access depends on the Claude GitHub App staying installed on the
  repo and the user's GitHub connector staying linked in claude.ai.
- `git fetch origin main && git reset --hard origin/main` before editing — the repo moves
  fast (currently past v80).
- To preview: the built-in browser can open the live URL, or run `start.bat` locally
  (needs Python; opening `index.html` via `file://` won't load the JSON data).

## Conventions that matter
- **Keep all asset paths relative** (`style.css`, `data/gsat.json`, `./`). The site is
  served from the `/vocab-app/` sub-path, so a leading-slash absolute path (`/style.css`)
  breaks it. `manifest.webmanifest` uses `start_url`/`scope` = `./` for the same reason.
- Service worker (`sw.js`) is **network-first** with a 6s timeout and offline cache
  fallback; the `CORE` array lists every file it precaches — add new runtime assets there.
- Theme colors live in `style.css` / settings; data is regenerated by `tools/build_*.py`
  (see README). Practice questions are transcribed from textbook photos and answer-checked
  against `tools/answers_all.txt`.
